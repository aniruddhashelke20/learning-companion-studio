Analysis

The Core Challenge

02 / 07

✕ Traditional LMS Limits

Standard Learning Management Systems (LMS) typically capture static HTTP page loads. They completely lack visibility into **how** learners digest course contents, watch videos, or answer quiz questions.

Missing Telemetry: Video skip speeds, scrolling activity depth, option changes on interactive quizzes, and navigation milestones.

✓ The LearnLog Solution

A standalone application containing a **Moodle-inspired telemetry pipeline**. Micro-interactions are registered on the client, validated on the server, and written to a MongoDB log database.

Google Sheet Sync: Real-time streaming allows analysts to view log events in spreadsheets instantly without raw database access.
Clickstream data allows educators to run engagement modeling, drop-out predictions, and course material quality evaluations.
Architecture

Full-Stack Data Flow

03 / 07
Step 1: Capture

React Frontend (Vite)

Captures button clicks, video play/seeks, page scrolls, and quiz options. Uses custom React contexts for authentication and dark mode.

Tailwind + Recharts
Step 2: Stream

Express API (Node.js)

Receives event payloads. Verifies event integrity, attaches client IP, and maps user IDs from JWT authorization headers.

Secure JWT Middleware
Step 3A: Log

MongoDB Database

Stores primary records: users, courses, lesson summaries, quiz submissions, and the event logging collection using Mongoose schemas.

Flexible Schemas
Step 3B: Sync

Google Sheets Webhook

Asynchronously pushes payload to a Google Apps Script Web App. Appends rows instantly to a Google Sheet. Non-blocking thread.

Apps Script Web App
The API endpoints are fully secured; only authenticated requests can trigger logs. 100% Non-Blocking Sync
Data Schema

Clickstream Log Schema

04 / 07
Field Type Telemetry Description
eventName String Event action identifier (e.g. `VIDEO_SEEKED`, `QUIZ_SUBMITTED`).
component String UI interface block where event fired (e.g. `VideoPlayer`, `QuizQuestion`).
eventContext String Parent entity context (e.g. Course Title: "Intro to Machine Learning").
ipAddress / origin String User IP location and channel source origin (e.g., `web`, `mobile`).
metadata Mixed/JSON Dynamic payload (e.g., `{ depth: "150px" }`, `{ score: 85 }`).
Telemetry Log Example
{
  "eventName": "VIDEO_SEEKED",
  "component": "VideoPlayer",
  "eventContext": "Introduction to ML",
  "resourceType": "video",
  "resourceId": "64cba3...",
  "metadata": {
    "currentTime": 102
  },
  "ipAddress": "127.0.0.1",
  "origin": "web"
}
This schema aligns closely with Moodle's standardized log table columns, making it instantly compatible with academic analysis tools.
Features

Learner Experience (LMS UI)

05 / 07

LMS Split-Pane Layout

Features an outline sidebar for lesson navigation, preventing full page reloads, and orienting students within the course.

Advanced Video Telemetry

Tracks play, pause, seek times, and video completion events. Connects browser media events directly to the Express logging routes.

Interactive Quiz Review

Students receive score results immediately. A detailed question log renders their chosen options vs. correct answers in red/green cards.

Standard web features like theme toggling (Light/Dark mode) are also mapped as event triggers to monitor UI preferences.
Analytics

Admin Console & Logs

06 / 07

Actionable Admin Dashboard

Admin console provides live aggregated stats on platform health, total learner sign-ups, and average assessment scores.

  • Visual Charts: Interactive Recharts bar graph displaying most common log actions.
  • Detailed Filtering: Live filter inputs for finding events by username or action type.
  • CSV Export: Instant raw clickstream file download for external Excel analysis.
